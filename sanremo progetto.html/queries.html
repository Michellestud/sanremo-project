SPARQL QUERIES

To carry out this project, we selected the ArCo knowledge graph as our primary data source, and proceeded to explore its contents through a series of preliminary SPARQL queries. These initial queries aimed to retrieve basic data about the Sanremo Music Festival.
With our first research, we discovered that this cultural event is currently not present in this knowledge graph under the names “Festival di Sanremo” or “Festival di San Remo”, considering both the subject and object positions of RDF triples. Having found no corresponding entities, we broadened the scope of the investigation by searching for resources associated with the keyword “festival” while maintaining the same query structure.

QUERY 1

PREFIX rdfs: <http://www.w3.org/2000/01/rdf-schema#>
PREFIX arco: <https://w3id.org/arco/ontology/cultural-heritage/>
PREFIX cis: <http://dati.beniculturali.it/cis/>
PREFIX a-ce: <https://w3id.org/arco/ontology/cultural-event/> 

SELECT DISTINCT ?s ?o
WHERE {
  { ?s a cis:CulturalEvent }
  UNION 
  { ?s a a-ce:RecurrentSituationSeries }
  UNION
  { ?s a a-ce:Competition }
  ?s rdfs:label ?o .
  
  OPTIONAL {
    ?s a arco:HistoricOrArtisticProperty ;
    a arco:CulturalProperty .
  }
  
  FILTER(
REGEX(STR(?s), "Festival di Sanremo|Festival di San Remo", "i") || REGEX(STR(?o), "Festival di San Remo", "i")
  )
}
ORDER BY ASC (?o)
LIMIT 50

With the second query, we found multiple entities within the ArCo database called “Festival”. We went through all of them and found no existing correspondence with the Sanremo Music Festival. We further expanded our search by looking for entities that contained “Sanremo” or “San Remo” in their labels. This approach allowed us to investigate whether the festival might be represented indirectly or under a different naming convention within the knowledge graph.

We subsequently performed an additional search looking for entities called “Teatro Ariston” in both subject and object positions.

QUERY 5

PREFIX rdfs: <http://www.w3.org/2000/01/rdf-schema#>
PREFIX arco: <https://w3id.org/arco/ontology/cultural-heritage/>
PREFIX cis: <http://dati.beniculturali.it/cis/>

SELECT DISTINCT ?s ?o
WHERE {
  { ?s a cis:CulturalEntity }
  UNION 
  { ?s a cis:Entity }
  ?s rdfs:label ?o .
  
  OPTIONAL {
    ?s a arco:HistoricOrArtisticProperty ;
    a arco:CulturalProperty .
  }
  
  FILTER(
    REGEX(STR(?s), "teatro Ariston", "i") || REGEX(STR(?o), "teatro Ariston", "i") 
   )
}
ORDER BY ASC (?o)
LIMIT 50

QUERY 5 RESULTS

As we obtained no correspondence, we concluded that the ArCo knowledge graph does not include an entity concerning the Sanremo Music Festival or the Teatro Ariston. Based on these findings, we decided to create and integrate relevant information into the knowledge graph from the beginning.

Explanation of the keywords we used

  • OPTIONAL — In SPARQL, OPTIONAL is used when a pattern is not required for a solution to be returned. If a matching value is found, it will be included in the result. If not, the variable remains unbound without invalidating the rest of the query and the solution will not be discarded.
  • DISTINCT — We used it to remove potential duplicates from the results.
  • UNION — With this keyword we combined multiple naming patterns and results from different triple patterns or queries. With UNION we can have a compilation of results from either one or another pattern.
  • FILTER and REGEX — The FILTER keyword is employed to restrict solutions over the group where FILTER appears, while REGEX makes entities easier to retrieve by establishing that if the value contains a specific name string, then the software will show results even if the name string appears inside a bigger string. We explicitly search for strings by combining REGEX with STR. “i” = It is employed to make the string case insensitive.
  • ORDER BY — We used it to order the results of the query with the ASC modifier so that the results of the object would be ordered with an ascending alphabetical order.
  • LIMIT — This keyword sets a limit on the number of elements to visualise in the results. We always set the LIMIT on 50 except for the second query, where we did not specify any limit in order to query all possible results.
